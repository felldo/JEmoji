# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

### Build

```bash
# Build all subprojects
./gradlew build

# Build only the main jemoji library
./gradlew :jemoji:build

# Build only the languages module
./gradlew :jemoji-languages:build
```

### Generate emoji data

The Java sources in `jemoji/build/generated/jemoji/` (`Emojis`, `EmojiGroup`, `EmojiSubGroup`, `EmojiLanguage`, `internal.PreComputedConstants`) and the data files (`jemoji/src/main/resources/jemoji/emojis.json`, `public/`, `jemoji-languages/src/main/resources/emoji_sources/`) are generated by the `emoji-generator` module — they are not hand-written.

```bash
# Generate emoji data (fetches from Unicode, CLDR, Discord, Slack, GitHub)
./gradlew generate

# Additionally writes all per-language files (jemoji-languages resources, public/description, public/keywords, public/emojis-full.json)
./gradlew generateAll
```

Set `GITHUB_TOKEN` (optional, any token, no scopes needed, e.g. `GITHUB_TOKEN=$(gh auth token) ./gradlew generate`) to avoid the unauthenticated GitHub API limit of 60 requests/hour, which a few local runs exhaust. Output files are only rewritten if their content changed (`writeTextIfChanged` in `Files.kt`).

`jemoji:compileJava` runs `generate` automatically if `jemoji/build/generated/jemoji/net/fellbaum/jemoji/Emojis.java` does not exist. The CI workflow `updateGeneratedFiles.yml` runs `generateAll` weekly and opens a PR.

The generator depends on `libs/jemoji.jar` (for `Fitzpatrick`/`HairStyle`/`EmojiManager`); after `:jemoji:build` the jar is copied there automatically.

```bash

./gradlew publishAll

# Publish a single subproject
./gradlew :jemoji:publish
```

Publishing requires `JEMOJI_SIGNING_SECRET_KEY_RING_FILE` to be set in Gradle properties.

## Architecture

### Module structure

This is a Gradle multi-project build with two publishable subprojects and the (unpublished) generator:

- **`jemoji`** — Core library (~600 KB). Contains `EmojiManager`, `Emoji`, `EmojiLoader`, and all emoji utility logic. Emoji data is loaded at runtime from `jemoji/src/main/resources/jemoji/emojis.json`.
- **`jemoji-languages`** — Optional language module (~13 MB). Provides descriptions and keywords in 160+ languages via `EmojiLanguage` enum. Loaded via Java `ServiceLoader` (`ResourceFilesProvider` SPI).
- **`emoji-generator`** — Kotlin application that generates all emoji data and Java sources (see below).
- **`buildSrc`** — Shared Gradle convention plugins (`myproject.java-conventions.gradle.kts`, `myproject.library-conventions.gradle.kts`).

### Code generation pipeline (`emoji-generator`)

Kotlin application in `emoji-generator/src/main/kotlin/net/fellbaum/jemoji/generator/`. `Main.kt` contains the whole pipeline in order; every other file is one step:

- `source/` — one file per external source, each returns plain data:
  - `UnicodeSource.kt` — latest `emoji-test.txt` and `emoji-variation-sequences.txt` from `unicode-org/unicodetools`, plus their parsers (`parseEmojiTestFile` builds the `GradleEmoji` list).
  - `DiscordSource.kt`, `SlackSource.kt` — aliases scraped from the web clients' JS assets (Slack via HtmlUnit). Discord falls back to the cached `emoji_source_files/discord-emoji-definition.json`.
  - `GitHubSource.kt` — aliases from the GitHub emoji API. The alias→emoji mapping is maintained by hand in `src/main/resources/github/aliases.json` + `emojis.json`; generation fails if the API's alias list changes (see KDoc of `fetchGitHubAliases` for the update procedure).
  - `CldrSource.kt` — descriptions/keywords per locale from `unicode-org/cldr-json` (derived annotations first, regular annotations override).
- `Translations.kt` — merges CLDR data into the emoji list (English keywords go into `emojis.json`; descriptions are spread to other qualifications of an emoji via the English description, which effectively only works for `en`).
- `codegen/` — JavaPoet generators: `EmojisInterfaceGenerator.kt` (`Emojis` + one interface per subgroup, max 900 constants each), `PreComputedConstantsGenerator.kt`, `EnumGenerators.kt`, shared helpers in `JavaPoetUtils.kt`. `Naming.kt` defines the public constant/enum names — changing it renames library API.
- `GeneratorPaths.kt` — every input/output path. `Http.kt`, `Json.kt` — shared HTTP client and Jackson mappers (`sortedJsonMapper` for published files).
- `model/GradleEmoji.kt` — the `emojis.json` format read by jemoji at runtime; don't rename/reorder fields.

Raw files from external services are cached in `emoji_source_files/`.

### Runtime emoji loading (`EmojiManager`)

`EmojiManager` uses lazy double-checked locking to initialize emoji data on first use:
- Unicode emoji maps are initialized on first call to any lookup/extraction method.
- Alias maps are initialized separately on first alias-related call.
- Language descriptions/keywords are lazily loaded per language on first access.

The `jemoji-languages` module integrates via `ServiceLoader<ResourceFilesProvider>` — the main `jemoji` module detects whether the language module is on the classpath at class-loading time.

### JPMS module system

Both `jemoji` and `jemoji-languages` ship a plain `module-info.java` in `src/main/java/` (`net.fellbaum.jemoji` and `net.fellbaum.jemoji.languages` respectively). Both modules compile with the Java 17 toolchain configured in `myproject.library-conventions.gradle.kts` — there is no `--release 8` constraint and no Java 8 compatibility target.

Note: earlier versions of this project built these as Multi-Release JARs (Java 8 base classes + a `META-INF/versions/9/` overlay carrying `module-info.class`). That setup was removed in commit `6249e71` ("Migrate to module system, refactor build scripts, and clean up Java 9-specific configurations"), which deleted the separate `java9` source sets, the `--patch-module` compiler wiring, and the `Multi-Release: true` jar manifest attribute. Do not reintroduce MRJAR assumptions when working on these modules unless explicitly asked to restore Java 8 support.

### Key classes

- `EmojiManager` — Public API for all emoji operations (extract, replace, remove, lookup by unicode/alias/HTML/URL).
- `Emoji` — Immutable value class representing a single emoji with all its metadata. Implements `Comparable<Emoji>` (not `Serializable`).
- `EmojiLoader` — Handles deserialization of emoji data and language file loading.
- `InternalEmojiUtils` — Internal string/codepoint utilities shared across the package.
- `InternalCodepointSequence` — Internal key type for alias lookup maps (handles colon normalization).
- `Emojis` — Auto-generated class with type-safe constants (e.g., `Emojis.THUMBS_UP`).

### Data flow summary

```
Unicode/CLDR/Discord/Slack/GitHub → emoji-generator (generate task)
  → jemoji/src/main/resources/jemoji/emojis.json (loaded at runtime by EmojiManager)
  → public/emojis.json → read back to generate Emojis.java & co. (jemoji/build/generated/jemoji)
  → public/*.json (public JSON files)
  → jemoji-languages/src/main/resources/emoji_sources/{description,keyword}/<locale>.json (generateAll only)
```
